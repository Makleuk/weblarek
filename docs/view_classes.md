## 2. Класс `Modal` 
**Назначение:** Управление модальным окном (открытие/закрытие, отображение контента).
**Расположение:** `src/components/Modal.ts`

### Поля класса:
| Поле | Тип | Описание |
|------|-----|----------|
| `container` | `HTMLElement` | Корневой DOM-элемент модального окна |
| `content` | `HTMLElement` | Элемент для размещения контента внутри модального окна |
| `closeButton` | `HTMLButtonElement` | Кнопка закрытия модального окна |

### Методы:
| Метод | Параметры | Возвращает | Описание |
|-------|-----------|------------|----------|
| `open()` | нет | `void` | Открывает модальное окно (добавляет класс `_active`) |
| `close()` | нет | `void` | Закрывает модальное окно (убирает класс `_active`) |
| `setContent(content: HTMLElement)` | `content: HTMLElement` | `void` | Устанавливает контент внутри модального окна |
| `render()` | нет | `void` | Отрисовывает модальное окно |

### События:
- `modal:open` - генерируется при открытии модального окна
- `modal:close` - генерируется при закрытии модального окна (клик по крестику или вне области)

## Принципы:
1. **Каждый класс отвечает за свой блок разметки** - один компонент = один template
2. **Наследование карточек** - три типа карточек наследуются от общего родителя `Card`
3. **Наследование форм** - две формы наследуются от общего родителя `Form`
4. **Modal не имеет наследников** - это самостоятельный компонент-контейнер
5. **События** - каждое действие пользователя генерирует событие для Prezenter'а
6. **Рендеринг** - каждый компонент имеет метод `render()` для отрисовки

## Реестр событий приложения

Все события генерируются классами представления и обрабатываются Презентером. Ниже приведен полный список событий с описанием передаваемых данных.

| Событие | Источник | Передаваемые данные | Описание |
|---------|----------|---------------------|----------|
| `modal:close` | `Modal` | `{}` | Пользователь закрыл модальное окно (клик по крестику или оверлею) |
| `card:select` | `CardCatalog` | `{ id: string }` | Клик по карточке товара в каталоге |
| `card:toggle` | `CardPreview` | `{ id: string }` | Клик по кнопке "В корзину" / "Удалить из корзины" в превью товара |
| `card:remove` | `CardBasket` | `{ id: string }` | Клик по кнопке удаления товара в списке корзины |
| `basket:click` | `HeaderView` | `{}` | Клик по иконке корзины в шапке сайта |
| `basket:checkout` | `BasketView` | `{}` | Клик по кнопке "Оформить" в окне корзины |
| `order:submit` | `OrderForm` | `{ payment: string, address: string }` | Отправка формы выбора оплаты и адреса |
| `contacts:submit` | `ContactsForm` | `{ email: string, phone: string }` | Отправка формы контактных данных |
| `success:close` | `SuccessMessage` | `{}` | Закрытие окна успешного оформления заказа |


## Реестр событий Модели (Model Events)

События генерируются моделями данных при любом изменении их состояния. Презентер подписывается на эти события, чтобы обновлять представление.

| Событие | Источник | Передаваемые данные | Описание |
|---------|----------|---------------------|----------|
| `catalog:changed` | `CatalogModel` | `{ items?: IProduct[], selected?: IProduct \| null }` | Изменен список товаров или выбран товар для просмотра |
| `basket:changed` | `BasketModel` | `{ items: IProduct[], total: number }` | Изменен состав корзины (добавление, удаление, очистка) |
| `buyer:changed` | `BuyerModel` | `IBuyer` | Изменены данные покупателя (оплата, адрес, контакты) |

## Презентер (Presenter)

### Описание подхода

В данном проекте реализован **единый Presenter** для всей страницы приложения. Код презентера находится в файле `src/main.ts` и не вынесен в отдельный класс, так как приложение состоит из одной страницы.

### Ответственность Presenter

Presenter отвечает за:
- Обработку всех событий от Моделей и Представлений
- Связывание слоёв Model и View
- Управление потоком данных между компонентами
- Координацию открытия/закрытия модальных окон
- Валидацию и передачу данных между формами

### Принципы реализации

1. **Presenter не генерирует события** — он только обрабатывает их
2. **Представления перерисовываются только при:**
   - Получении события от модели об изменении данных
   - Открытии модального окна
3. **Отсутствует прямая связанность** — все взаимодействия через события
4. **Инверсия зависимостей** — Presenter зависит от абстракций (интерфейсов), а не от конкретных реализаций

### Обработчики событий

#### События от Моделей:

| Событие | Обработчик | Действия |
|---------|------------|----------|
| `catalog:changed` | Обновление каталога | Получает товары из модели, создаёт карточки, рендерит галерею |
| `basket:changed` | Обновление корзины | Пересчитывает общую сумму, обновляет счётчик в шапке, рендерит список товаров в корзине |
| `buyer:changed` | Обновление данных покупателя | Валидирует форму, активирует/деактивирует кнопку отправки |

#### События от Представлений:

| Событие | Обработчик | Действия |
|---------|------------|----------|
| `card:select` | Выбор товара | Получает товар по ID из модели, открывает модальное окно с превью |
| `card:toggle` | Добавление/удаление из корзины | Добавляет или удаляет товар из модели корзины |
| `card:remove` | Удаление из корзины | Удаляет товар из модели корзины, закрывает модальное окно если корзина пуста |
| `basket:click` | Открытие корзины | Рендерит содержимое корзины, открывает модальное окно |
| `basket:checkout` | Оформление заказа | Открывает форму оформления заказа (первый шаг) |
| `order:submit` | Отправка формы заказа | Валидирует данные, сохраняет в модели, открывает форму контактов |
| `contacts:submit` | Отправка контактных данных | Валидирует, сохраняет, отправляет заказ на сервер, показывает успех |
| `modal:close` | Закрытие модального окна | Закрывает модальное окно, очищает контент |
| `success:close` | Закрытие успеха | Закрывает модальное окно, очищает корзину |

### Поток данных при оформлении заказа

1. Пользователь нажимает "Оформить" в корзине → `basket:checkout`
2. Открывается форма `OrderForm` с выбором оплаты и адреса
3. Пользователь заполняет форму → `order:submit`
4. Presenter валидирует данные через `BuyerModel.validate()`
5. Если валидация успешна → открывается `ContactsForm`
6. Пользователь вводит email и телефон → `contacts:submit`
7. Presenter собирает все данные, создаёт объект `IOrder`
8. Отправляет заказ через `LarekApi.createOrder()`
9. При успехе → показывает `SuccessMessage`, очищает корзину
10. При ошибке → показывает ошибки в форме

### Инициализация приложения

1. Создаются экземпляры всех моделей с передачей `EventEmitter`
2. Создаются экземпляры всех представлений с передачей `EventEmitter`
3. Устанавливаются все обработчики событий
4. Запрашиваются товары с сервера
5. Модель каталога сохраняет товары → генерирует `catalog:changed`
6. Presenter обрабатывает событие → рендерит галерею
